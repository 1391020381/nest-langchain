# 业务需求

## 1. 产品定位

产品暂定名为 **DeepAgent 需求分析工作台**。

它帮助产品经理、业务分析师和技术评审人员，把自然语言需求转成结构化、可追溯、可继续执行的需求分析报告。系统不是简单问答机器人，而是一个能规划任务、调用工具、委派专家、等待用户补充信息并产出文件的业务 Agent。

## 2. 目标用户

| 用户 | 核心诉求 |
| --- | --- |
| 产品经理 / 需求提出人 | 快速发现需求缺口，得到用户故事、范围、风险和验收标准 |
| 架构师 / 开发负责人 | 了解模块依赖、复杂度、性能影响和实施建议 |
| 安全 / 合规评审人 | 只关注与自己领域相关的结论，并能追溯依据 |
| 平台管理员 / 运维 | 查看运行状态、失败原因、成本、审计和质量指标 |

## 3. 核心业务场景

### 3.1 单需求分析

用户输入一条需求，例如：

> 用户希望能够批量导入 Excel 数据，单次最多 10,000 行，失败记录可下载。

系统应提取目标、角色、范围、约束和验收条件，选择需要的专家，最后生成一份综合报告。

### 3.2 信息不足时澄清

用户只输入“增加批量导入”时，系统不能直接编造数量限制、权限和失败处理方式。它应暂停当前运行，向用户展示结构化澄清问题；用户回答后，从同一个 thread 继续，而不是开启一份无关的新分析。

### 3.3 企业知识增强

用户上传产品说明、历史需求、安全规范或合规政策。分析时，Agent 可调用知识检索工具，并在报告中说明采用了哪些来源。知识库没有覆盖的事实必须明确标注，不能伪造内部规则。

### 3.4 多专家协作

复杂需求可能需要以下领域：

- 功能专家：模块拆解、用户流程、依赖、冲突与边界。
- 性能专家：负载特征、容量、时延、批量规模、瓶颈和优化建议。
- 安全专家：认证、授权、数据保护、威胁和审计要求。
- 合规专家：隐私、数据驻留、数据生命周期和适用规则。

根 Agent 根据需求选择专家，不要求每次无条件调用全部专家。每个专家只获得必要工具，并把结果写到独立产物，根 Agent 最后统一汇总。

### 3.5 多需求长链分析

用户一次提交多个明确编号的需求时，系统先生成 todos，再逐项或并行委派分析，最后给出跨需求依赖、资源冲突、整体风险和建议优先级。单项失败不得吞掉其他已完成结果。

### 3.6 受控业务操作

后续可把“创建需求单、同步项目管理系统、更新状态”等能力做成工具。只读工具可按权限自动调用；产生外部副作用的写工具必须先展示操作摘要并等待人工批准。

## 4. 功能需求

### FR-01 会话与需求输入

- 创建新会话，并在会话中提交单条或多条需求。
- 支持继续追问，能理解最近会话上下文。
- 支持取消正在执行的分析。
- 每次运行具有独立 `runId`，会话具有稳定 `threadId`。

### FR-02 需求抽取与完整性判断

系统至少抽取以下信息：

- 标题、背景、目标用户和业务目标。
- 需求类型和优先级。
- 功能范围、非目标和依赖。
- 性能、安全、权限、审计、合规等约束。
- 验收标准和待确认问题。

当关键字段不足时，返回澄清请求，而不是直接生成看似完整的报告。

### FR-03 规划与执行

- 根 Agent 使用 todo 计划表达当前任务和状态。
- 计划变化能够被转换成前端可理解的进度事件。
- 运行必须有最大循环/递归限制、超时和取消信号。
- 已完成任务要有确定的收口条件，避免重复委派或无限读取文件。

### FR-04 专家选择与协作

- 根 Agent 根据需求维度选择必要专家。
- 专家拥有独立 Prompt、工具白名单和输出路径。
- 专家可并行，但不得并发覆盖同一个单值状态或同一个产物。
- 根 Agent 只汇总已完成的专家结果，并标出失败或缺失部分。

### FR-05 工具与知识

首期工具分为：

- 需求工具：查找相似需求、读取需求详情、检测冲突。
- 知识工具：检索产品文档、架构规范、安全基线和合规政策。
- 分析工具：完整性评分、复杂度估算等确定性计算。
- 产物工具：写入、读取和列出本次运行的工作文件。
- 外部动作工具：创建或同步业务记录，必须经过授权和人工确认。

### FR-06 分析结果

综合报告至少包含：

- 需求摘要和明确假设。
- 完整性结论与待确认项。
- 功能、性能、安全、合规分析。
- 依赖、冲突、风险和缓解建议。
- 复杂度等级与实施拆分建议。
- 用户故事和可执行验收标准。
- 知识来源、参与专家、工具使用摘要和运行状态。

### FR-07 实时反馈

前端展示的是稳定的业务事件，而不是直接消费所有底层 LangChain 事件。至少支持：

- `run.started`
- `plan.updated`
- `agent.progress`
- `tool.progress`
- `clarification.required`
- `artifact.updated`
- `report.completed`
- `run.failed`
- `run.done`

事件必须携带 `runId`、`threadId` 和时间戳。底层事件名称只用于服务端诊断，不能成为 Web 端长期契约。

### FR-08 产物与持久化

- 用户可在 Web 端查看和下载报告及专家产物。
- 会话、消息、运行、todo、产物元数据和最终状态可持久化。
- 服务重启后仍能查看已完成运行；可恢复的中断任务能从同一 thread 继续。
- DeepAgent 的 `/work` 是虚拟路径，不等于仓库根目录下的真实文件夹。业务层必须显式把产物从 Backend 导出到数据库、对象存储或受控磁盘目录。

### FR-09 人工确认

- 信息澄清、关键假设确认和高风险外部写操作支持暂停/恢复。
- 恢复请求必须校验用户、会话、运行和待审批动作的一致性。
- 拒绝操作后应得到明确终态，不能让运行永久停在“执行中”。

### FR-10 管理与诊断

- 健康检查区分进程存活和模型/数据库/向量库等依赖就绪。
- 可按 `traceId`、`runId`、`threadId` 关联日志。
- 记录延迟、token、调用次数、失败类型和各 Agent 耗时，但日志不写入需求正文、密钥或敏感工具参数。

## 5. 非功能需求

| 维度 | 最低要求 |
| --- | --- |
| 安全 | 密钥不返回前端；输入注入检测；工具白名单；租户数据隔离；写操作审批 |
| 可靠性 | 超时、重试、取消、幂等；单专家失败可降级；SSE 心跳和明确终态 |
| 可观测性 | 结构化日志、trace/run/thread 关联、模型与工具级指标、成本统计 |
| 可测试性 | 纯函数/协议测试、stub model 集成测试、真实模型可选测试、Browser E2E |
| 性能 | 首个进度事件快速返回；长步骤用心跳保活；专家并行以实际收益为准 |
| 可维护性 | Prompt、工具、Agent、运行时、事件适配和存储相互隔离 |
| 兼容性 | OpenAI-compatible 模型必须支持 tool calling；版本必须锁定并验证 |

## 6. 范围边界

### 首期范围内

- 文本需求输入与结构化澄清。
- 单需求和多需求分析。
- DeepAgent 根 Agent、领域子 Agent、todos、VFS 和持久化 thread。
- 知识上传、检索和来源展示。
- 实时进度、报告、产物查看与下载。
- 受控工具调用、取消、错误提示、审计和基本评估。

### 首期范围外

- 自动修改业务仓库并直接提交 PR。
- 无人工审批地写入外部生产系统。
- 训练或微调专有模型。
- 一开始就实现 Graph-RAG、复杂 Swarm 或远程异步 Agent 集群。
- 同时维护一套手写 LangGraph 业务流程作为备用主链。

## 7. 最终端到端验收故事

1. 用户登录并创建会话。
2. 上传一份产品批量导入规范和一份安全基线。
3. 输入一条信息不完整的批量导入需求。
4. 系统实时展示规划，并要求补充数量上限、权限和失败处理方式。
5. 用户提交澄清信息，原运行恢复。
6. Agent 检索两份企业文档，选择功能、性能和安全专家。
7. 页面实时显示专家和工具进度，用户可以取消。
8. 系统生成综合报告、用户故事和验收标准，并标出引用来源。
9. 用户重启服务后仍可打开该会话和下载产物。
10. 日志和指标可以根据同一 `runId` 定位本次运行的耗时、错误和 token 成本。
