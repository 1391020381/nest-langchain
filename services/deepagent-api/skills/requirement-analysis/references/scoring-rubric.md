# 六维需求评分表

| 维度 | 检查重点 | 信息充分的表现 |
| --- | --- | --- |
| 用户与场景 | 谁在什么上下文使用 | 至少有一个明确角色和触发场景 |
| 目标与价值 | 为什么要做 | 描述预期业务或用户结果 |
| 功能范围 | 做什么、不做什么 | 核心流程、输入、输出和排除项明确 |
| 验收标准 | 如何判断完成 | 有可观测、可重复验证的结果 |
| 非功能要求 | 质量约束 | 性能、安全、权限、可用性等按需说明 |
| 边界与例外 | 异常如何处理 | 数量边界、失败路径和恢复策略明确 |

评分只是发现缺口的提示，不代替产品判断。若输入没有提供某项信息，应提出问题，不应自行补全。
